# 생성자-QA 자율 루프 설계

- 작성일: 2026-06-03
- 상태: 설계 승인 대기
- 목표: 로드맵 1순위 잔여 항목을 **생성자 에이전트 → QA 에이전트 → 수정 반복** 루프로 자율 구현하고, 모든 과정을 기록한다.

## 배경

[MVP 이후 로드맵](../plans/2026-06-01-post-mvp-roadmap.md)의 1순위(RSC/SSR 마이그레이션)에 미완료 항목 5개가 남아 있다.
이를 사람이 하나씩 시키는 대신, 에이전트 루프가 자율적으로 구현 → 검증 → 수정을 반복하고
사람은 전체 완료 후 한 번만 확인한다.

## 전체 구조

```
[Phase 0: 사전 준비 — 1회만]
  CLAUDE.md 생성 → main을 feat/data-foundation까지 fast-forward → main + 브랜치 푸시
  ✅ 완료: GitHub 원격 연결 (so098/landing-page-showcase, SSH 인증 확인)
  ✅ 완료: GitHub MCP 설치 (.mcp.json — https://api.githubcopilot.com/mcp/)
  ※ 사람 필요: GitHub MCP 승인 + OAuth 인증 (/mcp)

  > main fast-forward 이유: 현재 main은 78커밋 뒤처진 초기 스냅샷.
  > 이대로 푸시하면 GitHub 첫 화면(main)에 빈 프로젝트가 보인다.
  > main은 feat/data-foundation의 순수 조상이므로 fast-forward는 이력 손실 없이 안전.

[Phase 1: 자율 루프 — 메인 세션 오케스트레이션]
  5개 항목 순서대로:
  ① 생성자 에이전트: 구현 + 테스트 작성
  ② QA 에이전트: 검증 (playwright 스위치 + CLAUDE.md 기준)
  ③ 허점 발견 → 생성자 수정 → ② 재검증 (QA가 "허점 없음" 판정할 때까지)
  ④ 허점 수정 시마다 docs/고친허점.md에 기록
  ⑤ 합격 → 커밋 + 푸시
  ⑥ 감시자 에이전트: GitHub MCP로 푸시된 커밋 확인 + 리뷰
  ⑦ 로드맵 체크박스 [x] 갱신 → 다음 항목

[Phase 2: 최종 보고]
  전체 결과 보고서 + 사람이 브라우저로 확인할 가이드
```

## 결정 사항

| 결정 | 선택 | 이유 |
|---|---|---|
| 실행 엔진 | **메인 세션 직접 오케스트레이션** (Agent 도구) | 예상 밖 상황에 유연하게 대처. 루프 규칙은 오케스트레이터(메인 세션)가 준수 |
| QA 기준 | **CLAUDE.md 먼저 생성** 후 그것을 기준으로 검증 | 레포 컨벤션(테스트 패턴, 커밋 스타일, 아키텍처)을 명문화 |
| 허점 판단 | **QA 에이전트 자율 판단** | 고정 라운드 제한 없음. "허점 없음" 판정까지 반복 |
| 허점 기록 | **`docs/고친허점.md`** | 허점 발견·수정마다 기록 — 포트폴리오 증거물로도 활용 |
| 범위 | **1순위 잔여 5개 항목만** | 외부 서비스 의존 없이 전부 자동화 가능 |
| 사람 개입 | **전부 끝나면 한 번만** | 자율 실행 + 최종 1회 확인 (사용자 워크플로 선호) |
| GitHub | **레포 생성 + 푸시 + GitHub MCP 커밋 감시** | 커밋마다 푸시 → 감시자가 GitHub에서 확인 |

## 처리할 5개 항목 (의존성 순서)

| 순서 | 항목 | playwright 스위치 | 의존성 |
|---|---|---|---|
| 1 | 홈 리뷰 리스트: Prisma `Review` 모델 + 시드 + `GET /api/reviews` + 홈 섹션 + ISR/`revalidateTag("reviews")` | **ON** | 없음 |
| 2 | 메타데이터/SEO: 페이지별 `generateMetadata`, OG 태그 | **ON** | 없음 |
| 3 | ShowcaseGrid 슬라이더 페이지네이션 RTL 테스트 | OFF | 없음 |
| 4 | 메인 `/` 페이지 E2E: 로드 → 필터 → 모달 열기 | **ON** | 1, 2 (홈 변경 반영) |
| 5 | After 측정: Lighthouse/LCP + README Before/After 표 | **ON** | 1~4 전부 (모든 변경 반영 후 측정) |

## 에이전트 정의 (`.claude/agents/`에 저장 — 세션 간 재사용)

### `generator.md` (생성자)
- **입력**: 로드맵 항목 1개 + (수정 라운드면) QA가 발견한 허점 리스트
- **행동**: 기존 코드 패턴 분석 → TDD로 구현 (테스트 먼저) → 테스트 통과 확인
- **제약**: CLAUDE.md 컨벤션 준수, 항목 범위 밖 수정 금지
- **출력**: 구현 요약 + 변경 파일 목록 + 테스트 결과

### `qa-reviewer.md` (QA)
- **입력**: 항목 + 생성자의 구현 요약 + playwright 스위치 값
- **행동**:
  1. CLAUDE.md 기준 코드 검토
  2. 전체 테스트 실행 (vitest + 기존 테스트 회귀 확인)
  3. 스위치 ON이면 → playwright MCP로 실제 브라우저 구동 검증
- **판단**: 무엇이 허점인지, 통과인지 **에이전트가 자율 판단**
- **출력**: `통과 여부 + 허점 리스트 [{심각도, 설명, 파일, 재현 방법}]`

### `watcher.md` (감시자)
- **입력**: 푸시된 커밋 SHA
- **행동**: GitHub MCP로 커밋이 GitHub(`so098/landing-page-showcase`)에 올라갔는지 확인 + 커밋 diff 검사
- **검사 항목**: 커밋 메시지 컨벤션, diff에 의도하지 않은 파일(시크릿, .env, 대용량) 포함 여부, 변경 범위가 항목 범위와 일치하는지
- **출력**: 이상 발견 시 보고 (다음 항목 진행 전 처리)
- **원칙**: 모든 커밋은 푸시 후 GitHub MCP 검사를 통과해야 다음 항목으로 진행

## 허점 기록 형식 (`docs/고친허점.md`)

```markdown
# 고친 허점 기록

## <N>. <항목명>
### 허점 <M> (QA 라운드 <R>에서 발견)
- **발견**: <허점 설명 + 재현 방법>
- **수정**: <수정 내용 + 변경 파일>
- **재검증**: QA 라운드 <R+1> 통과 ✅
```

## 안전장치

- **회귀 방지**: QA가 매번 기존 테스트 전체 실행 — 새 구현이 기존 기능을 깨면 불합격
- **DB 스키마 변경**(Review 모델): Prisma 마이그레이션 파일로 처리, 롤백 가능
- **브랜치 격리**: fast-forward된 main에서 새 브랜치 `feat/roadmap-p1-completion` 분기 — 루프의 모든 커밋은 이 브랜치에. 끝나면 사람이 PR 확인 후 main에 머지
- **루프 정체 감지**: QA가 같은 허점을 반복 지적하며 진전이 없으면 오케스트레이터가 중단하고 사람에게 보고 (어설픈 통과보다 정직한 중단)
- **GitHub 감시 실패**: 푸시 실패 또는 감시자가 이상 발견 시 다음 항목 진행 중단

## 데이터 흐름

```
로드맵 체크리스트 (md 파싱)
  → 생성자: 항목 + CLAUDE.md → 구현 + 변경 파일 목록
  → QA: 변경 파일 목록 + CLAUDE.md + playwright 스위치 → 허점 리스트 or 통과
  → (허점 시) 생성자: 허점 리스트 → 수정 → 고친허점.md 기록
  → (통과 시) 커밋 + 푸시 → 감시자: 커밋 SHA → GitHub 확인
  → 로드맵 체크박스 갱신
```

## 테스트 전략

각 항목 자체가 테스트를 포함한다(로드맵 원칙 1). QA는:
1. 생성자가 작성한 테스트가 실제로 기능을 검증하는지 확인 (형식적 테스트 거부)
2. 기존 테스트 전체 회귀 실행
3. UI 항목은 playwright로 실제 브라우저 동작 확인
