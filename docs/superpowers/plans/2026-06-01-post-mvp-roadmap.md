## 단계 1: 로그인 진짜로 만들기 → 사람이 확인

**목표**: 목 로그인(localStorage) → 실제 카카오 OAuth 로그인

**작업**
- [ ] 카카오 개발자 콘솔에서 앱 등록 + REST API 키·시크릿 발급 **(사람이 직접)**
  - redirect URI: `http://localhost:4000/api/auth/kakao/callback`
- [ ] api: Prisma `User` 모델 추가 (마스터 스펙 ③ 참고) + 마이그레이션
- [ ] api: `GET /api/auth/kakao` (시작) → `GET /api/auth/kakao/callback` (JWT 발급, httpOnly 쿠키)
- [ ] api: `GET /api/auth/me` (현재 로그인 사용자), `POST /api/auth/logout`
- [ ] web: 로그인 모달의 "카카오로 시작하기" → 실제 OAuth 시작 URL로 이동
- [ ] web: `lib/auth.ts`를 localStorage → `/api/auth/me` 호출 기반으로 교체
- [ ] 채팅 visitorId → 로그인 시 userId로 연결 (대화 이어가기)

**사람이 확인할 것**
1. 실제 내 카카오 계정으로 로그인 → 헤더에 카카오 프로필 이름 표시
2. 새로고침해도 로그인 유지
3. 로그아웃 → 다시 비로그인 상태

---

## 단계 2: 신청서 접수 → 내 메일로 전송

**목표**: 주문서 제출(생성하기/사람에게 주문하기)이 실제로 **내 메일(szerohan@gmail.com)** 로 도착

**작업**
- [ ] api: Prisma `Order` 모델 추가 + `POST /api/orders` (주문서 내용 DB 저장)
- [ ] api: 메일 발송 — **Resend**(추천, 무료 100통/일) 또는 Nodemailer + Gmail 앱 비밀번호
  - Resend 가입 + API 키 발급 **(사람이 직접)**
  - 주문 접수 시: 주문서 전체 내용을 정리한 메일을 `szerohan@gmail.com`으로 발송
- [ ] web: 주문서 제출 → sessionStorage 대신 `POST /api/orders` 호출
- [ ] web: 마이페이지 결제내역 목데이터 → `GET /api/orders` (내 주문) 실데이터로 교체

**사람이 확인할 것**
1. 주문서 작성 → 생성하기 클릭 → **내 Gmail에 주문 내용 메일 도착**
2. 마이페이지에 방금 한 주문이 표시됨

---

## 단계 3: 결제 (PortOne 테스트모드)

**목표**: 주문 시 실제 결제 흐름 (테스트 카드)

**작업**
- [ ] PortOne(구 아임포트) 가입 + 테스트모드 채널 키 발급 **(사람이 직접)**
- [ ] api: Prisma `Payment` 모델 + `POST /api/payments/verify` (서버 금액 검증)
- [ ] web: 주문서 제출 후 결제 단계 추가 — PortOne 결제창 호출
  - 첫 페이지 10,000원 / 추가 페이지 +10,000원 / AI 추가 제작 50,000원 / 사람 제작 300,000원
- [ ] 결제 성공 → Order 상태 PAID → 그 다음에 생성/채팅 흐름 진행
- [ ] 결제 실패/취소 처리

**사람이 확인할 것**
1. 주문 → 결제창 뜸 → 테스트 카드로 결제 → 성공 화면
2. 마이페이지에서 결제 금액·상태(PAID) 확인
3. 결제 취소 시 주문이 진행되지 않음

---

## 단계 4: 채팅 마무리 검증 + 운영 보강

**목표**: 이미 구현된 실시간 채팅을 운영 가능한 수준으로

**작업**
- [ ] 사람이 2개 브라우저로 직접 검증 (고객 ↔ /admin/chat)
- [ ] /admin/chat 접근 보호 — 단계 1의 로그인 + 관리자 계정만 접근
- [ ] 채팅과 주문 연결 — 인박스에서 이 고객의 주문서 내용 바로 보기
- [ ] (선택) 미응답 알림: 고객 메시지가 N분간 미읽음이면 내 메일로 알림

**사람이 확인할 것**
1. 고객으로 문의 → 관리자 인박스에서 실시간 수신 + 답장
2. 관리자가 아닌 사람은 /admin/chat 접근 불가
3. 인박스에서 고객 주문서 내용 확인 가능

---

## 단계 5: 진짜 랜딩페이지 넣기

**목표**: 목업 미리보기 → 실제 랜딩페이지 이미지/페이지

**작업**
- [ ] 실제 랜딩페이지 제작물(이미지 또는 HTML) 준비 **(사람이 직접 — 디자인 작업)**
- [ ] MinIO 버킷 연결 (마스터 스펙 ②-b): 업로드 스크립트 + presigned/공개 URL
- [ ] Showcase의 `desktopKey`/`mobileKey`에 실제 파일 연결 → API가 URL 반환
- [ ] iframe 미리보기에 실제 페이지 표시 (이미 `interactive` 모드 구현됨 — URL만 넣으면 동작)
- [ ] 생성 결과 페이지도 실제 생성물 URL 표시

**사람이 확인할 것**
1. 쇼케이스 카드/모달에서 실제 랜딩페이지가 보임 (스크롤 가능)
2. 주문 → 생성 결과에서 실제 페이지 확인

---

## 진행 순서 요약

```
1. 로그인 (카카오 OAuth)          ← 사람: 카카오 앱 등록 + 로그인 확인
2. 신청서 → 메일 전송              ← 사람: Resend 키 발급 + 메일 수신 확인
3. 결제 (PortOne 테스트)           ← 사람: PortOne 가입 + 테스트 결제 확인
4. 채팅 운영 보강                  ← 사람: 2브라우저 검증 + 관리자 보호 확인
5. 진짜 랜딩페이지 넣기            ← 사람: 실제 디자인 준비 + 표시 확인
```

각 단계는 독립적으로 **스펙 → 구현 → 사람 확인** 사이클을 따른다.
단계 1~3은 외부 서비스 키 발급(사람 작업)이 선행되어야 하므로, 시작 전에 키부터 준비한다.
