# 고친 허점 기록

> 생성자-QA 자율 루프에서 QA가 발견하고 생성자가 수정한 허점들. (포트폴리오 증거물)

## 1. 홈 리뷰 리스트 (로드맵 1순위)

### 허점 1 (QA 라운드 1에서 발견)
- **발견**: 검증 실패 시 입력값이 유지되지 않음 — 설계서 §4 에러 처리 표의 "폼 검증 실패 → 필드별 에러 메시지, 입력값 유지" 요구사항 미충족.
  - 재현: 홈 폼에 이름 `김`, 내용 `짧음` 입력 → 후기 등록 클릭 → 에러 메시지는 표시되나 이름/내용 입력칸이 둘 다 빈 값으로 초기화됨.
  - 원인: input/textarea가 비제어(uncontrolled)인데 제출값을 되돌려주는 경로가 없었음. `ReviewFormState`에 제출값을 에코하는 필드가 없었음.
- **수정**:
  - `apps/web/src/app/actions/reviews.ts`: `ReviewFormState`에 `values?: { authorName?; body? }` 추가. 검증 실패 및 제출 실패(네트워크/서버) 시 제출값을 `values`로 에코해 반환.
  - `apps/web/src/components/ReviewForm.tsx`: input/textarea에 `defaultValue={state.values?.…}` 적용. 비제어 요소는 리렌더만으로 `defaultValue`가 갱신되지 않으므로 `key`를 `state.values`에 묶어 새 실패 state 도착 시 리마운트해 값을 복원. 성공 시에는 기존 `formRef.reset()` 유지.
  - 테스트: `ReviewForm.test.tsx`에 "검증 실패 시 입력값을 유지한다" 추가 (TDD — 수정 전 실패, 수정 후 통과).
- **재검증**: QA 라운드 2 통과 ✅ (브라우저 재검증 — 입력값 유지·중복 1건만 저장 확인)

### 허점 2 (QA 라운드 1에서 발견)
- **발견**: 빠른 연타 제출 시 동일 리뷰가 중복 저장됨.
  - 재현: 유효값 입력 후 제출 버튼을 동기적으로 2회 연속 클릭 → DB에 동일 리뷰 2건 생성, 목록에 동일 카드 2개 노출.
  - 원인: `useFormStatus().pending` 기반 버튼 비활성화는 React 리렌더 이후에야 적용되어, 그 전의 두 번째 클릭을 막지 못함.
- **수정**:
  - `apps/web/src/components/ReviewForm.tsx`: `isSubmittingRef`(ref 기반) 동기 가드 도입. form action을 `guardedAction`으로 래핑해 진행 중이면 두 번째 제출을 동기적으로 무시. 액션 완료로 새 state가 도착하면(`useEffect([state])`) 가드를 해제해 재제출 허용.
  - 테스트: `ReviewForm.test.tsx`에 "연속 클릭해도 액션은 한 번만 호출된다" 추가 (지연 액션 + 동기 2회 클릭으로 재현; 수정 전 callCount 2 → 수정 후 1).
- **재검증**: QA 라운드 2 통과 ✅ (브라우저 재검증 — 입력값 유지·중복 1건만 저장 확인)
