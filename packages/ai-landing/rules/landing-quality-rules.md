# landing-templates — 빌드 규칙 (서브에이전트 필수 준수)

이 저장소는 업종별 랜딩페이지를 만든다. **랜딩을 만들거나 고치는 모든 작업(서브에이전트 포함)은
아래 규칙을 반드시 지킨다.** 규칙은 사용자가 반복 피드백으로 확정한 것이며, `scripts/score_landing.py`
정적 채점 + `.claude/hooks/` 훅으로 강제된다. 상세 근거·히스토리는 자동 메모리(`MEMORY.md` 및
`memory/feedback_*.md`)에 있다.

## 프로젝트 구조
- `templates/`, `templates2/` — 각 하위 폴더가 랜딩 1개. 진입점은 `index.html` (+ `styles.css`/`script.js`).
- `assets/<category>/` — 업종별 이미지 풀(업종당 70~100장). 랜딩 빌드의 1차 이미지 소스.
- `reference-images/` — **디자인 레퍼런스 전용**(실제 페이지에 넣지 말 것).
- `scripts/score_landing.py` — 품질 정적 채점(0~100). `scripts/shoot_templates.mjs` — 전체 데스크톱/모바일 스크린샷.
  `scripts/shoot_one.mjs <index.html> [outdir]` — 단일 페이지 스크린샷(비주얼 QA용) + **AP-10 폴드 측정 자동 출력**(⚠️ 초과/✅ OK).
  `scripts/check_fold.mjs <index.html>` — 헤더+hero 폴드 실측. **현실적인 화면 높이 7종**(FHD/900/맥북 820·780/노트북 720/모바일 844·667)
  전부 ✅여야 완료. 1440×900에서만 맞으면 안 됨 — hero 콘텐츠는 `@media (max-height:…)`로 낮은 화면에서도 압축되게.
- `.claude/agents/visual-qa.md` — 비주얼 QA 서브에이전트(`subagent_type: visual-qa`).

## 필수 규칙 (MUST)
- **AP-8 마퀴 금지**: coral 배경 + ◆ separator 무한 스크롤 띠 금지. 슬로건은 정적 텍스트나 chip 그리드로.
- **AP-9 픽토그램 카드 금지**: 시술/분류 카드의 중앙 SVG 픽토그램 금지 → 배경 이미지 + 다크 알파
  오버레이 카드로. (추상 컨셉 카드만 SVG 예외)
- **AP-10 hero 꽉 채움**: hero 배경 이미지는 viewport를 꽉 채운다(`object-fit:cover`, `min-height:100vh/100svh`,
  hero 자체에 base gradient). 이미지가 작으면 지배색 그라데이션으로 채운다. `object-fit:contain/fill/none` 금지.
  **주의**: `min-height`는 콘텐츠가 길면 hero가 폴드를 넘어 늘어난다 — CSS만 믿지 말고 `scripts/check_fold.mjs`로
  실측해 **7개 viewport 전부** 초과 4px 이하인지 확인할 것. hero 콘텐츠의 고정 높이(패딩·마진·고정px 요소)가
  화면 높이보다 크면 어떤 min-height를 줘도 넘친다 — `@media (max-height:860px)`, `(max-height:740px)` 류
  높이 미디어쿼리로 패딩·마진·서브 요소를 단계적으로 압축한다.
  **다중 배경 레이어 순서**: `background: url(사진), 그라데이션` 순서(사진이 위). 불투명 그라데이션을 사진보다
  앞(위)에 쓰면 사진이 완전히 가려진다(score_landing.py가 -20 감점). 가독성 오버레이는 반투명(rgba)만 사진 위에 허용.
  **헤더 + hero = 정확히 한 화면**: sticky 헤더(흐름에 포함)는 hero를 `min-height:calc(100vh - 헤더높이px)` +
  `calc(100svh - 헤더높이px)`로 잡아 첫 화면이 스크롤 없이 딱 떨어지게(다음 섹션이 폴드 바로 아래에서 시작).
  fixed 헤더(오버레이)는 hero `100vh/100svh` 그대로. 모바일에서 헤더 높이가 달라지면 미디어쿼리로 calc 값도 보정.
- **AP-11 인라인 폼 금지**: `<form>`/`<input>`/`<select>`/`<textarea>` 인라인 예약·문의 폼 금지.
  `#book` anchor는 유지하되 전화·카톡채널·외부 예약 URL **정적 패널**로 대체. (예외: `dental-implant-landing`)
- **AP-12 asset 풀 적극 사용**: 보유 이미지 풀에서 **페이지당 20~40장 실제 사용**. 슬롯만 갈아끼우는
  디자인 돌려쓰기 금지 — 이미지 주도 재설계가 디폴트.
- **AP-13 얼굴 노출 정책**: 성형외과 이벤트·미용 마케팅은 **이쁜 모델 얼굴을 크게·반복 노출**(수술/OR/
  마스크/주사 장면 금지). 일반 의료는 반대로 얼굴 회피(AP-1).
- **AP-14 거대 hero 헤드라인 금지**: hero 첫 문구(메인 헤드라인)를 viewport를 가득 채우거나 넘치는 초대형·heavy(800~900) 한글로 쓰지 말 것. 데스크탑 hero headline은 약 `clamp(1.9rem,4.2vw,3.1rem)`(≈30~50px)·2~3줄 이내로 정돈, weight 기본 600~700(900 남발 금지). 모바일에서 글자가 잘리거나 가로로 넘치지 않게.
- **AP-15 고급 업종 hero 타이포**: 디저트·와인바·레스토랑 등 '고급스러움'을 내세우는 페이지는 hero 첫 문구를 (a) 얇은 고딕(Noto Sans KR 300 또는 Pretendard 200~300 + 넓은 letter-spacing) 또는 (b) 영어 흘림체/스크립트 폰트(Google Fonts 'Parisienne'·'Pinyon Script'·'Great Vibes' 등, fallback `cursive`)로 우아하게. 한글 얇은 고딕 + 영어 스크립트 강조 조합 권장. 명조/serif 금지는 유지(영어 script는 cursive 계열이라 허용).
- **AP-16 과시성 숫자 통계 밴드 금지**: 큰 숫자 + 작은 라벨을 3~4개 나열한 '성과/통계/카운터' 띠(hero 하단 stat row, 별도 stats 밴드, num-card 카운트업 등)를 만들지 말 것. 특히 억지·검증불가 수치(예: "0 인공첨가물", "18h 발효", "312개 가맹", "97% 생존율", "100% 당일소진"). 신뢰는 실제 사진·메뉴·후기·정보로 전달한다. (단, 가격표·영업시간·픽업 리드타임·보관온도 같은 실제 사실 정보 표기는 허용.)
- **AP-17 hero 레이아웃 다양화 (동일 공식 복제 금지 / 우측 정렬 금지)**: 모든 페이지 hero를 동일 공식(좌측 eyebrow칩 + 헤드라인 + 버튼 2개 + 키워드 칩 행)으로 복제하지 말 것. 다양성은 '구성'으로 확보 — 중앙 정렬, 하단 앵커, 좌우 split(텍스트는 좌측 패널·사진은 우측), 미니멀 등. **단 hero 본문 텍스트를 우측 정렬하지 말 것(어색함).** 글자·버튼이 가벼우면 **좌측 정렬이 자연스럽고 권장** — 좌측 정렬 자체는 문제가 아니며, 문제는 키워드 칩·버튼 남발과 10개 페이지 동일 복제였다. hero에 키워드 칩 행을 습관적으로 깔지 말 것. **"풀블리드 배경사진 + 중앙 eyebrow/제목/리드 + 하단 SCROLL 큐" 공식도 동일 복제 금지 대상**(template6에서 10페이지 복제로 적발) — 한 그룹(폴더) 안에서 같은 hero 구성은 최대 2개까지만.
- **AP-18 한글 단어 중간 줄바꿈 금지**: 한글 텍스트가 '굽습'/'니다'처럼 어절(단어) 중간에서 잘려 줄바꿈되지 않게 할 것. 텍스트 컨테이너(기본 `body` 전역 + 헤드라인)에 `word-break:keep-all`을 적용해 공백 기준으로만 줄바꿈하고, 긴 어절 오버플로 방지로 `overflow-wrap:break-word`(또는 anywhere)를 병행한다.
- **AP-19 헤더–첫 섹션 공백 금지**: sticky 헤더(nav)와 첫 섹션(hero) 사이에 의도치 않은 빈 공백 띠가 생기지 않게 할 것. 특히 풀블리드/split hero가 전역 `section{padding:…}` 규칙을 상속해 상단(또는 사진 그리드 위)에 빈 띠가 생기는 경우 — hero는 padding을 직접 제어한다(보통 `padding:0` 또는 의도된 값). 첫 섹션 콘텐츠는 헤더 바로 아래에서 flush로 시작.
- **AP-20 인물은 한국인만**: 이미지에 사람이 등장하면 **한국인(국내/동양인) 컷만** 사용한다. 외국인(서양인·해외 스톡 등) 인물 컷 금지. 사람보다 건물·공간·인테리어·제품 컷을 우선하고, 인물 컷이 필요하면 한국인 컷으로. (얼굴 회피가 기본인 업종은 가능하면 peopleless 우선.)
- **AP-21 배경 없는 첫 화면 금지**: 첫 화면(hero)에는 **반드시 asset 풀의 실제 사진을 배경**으로 깐다(풀블리드 cover 또는 split 사진 패널). 단색·그라데이션·패턴만으로 된 텍스트-only 첫 화면 금지. 기본 공식은 "배경 사진 + 다크 오버레이 + 또렷한 텍스트". `score_landing.py`가 hero 스코프에 사진 배경(`url(...)` 또는 `<img>`)이 없으면 -20 감점.
  단, 이 공식(배경사진+중앙 텍스트+SCROLL 큐)도 **전 페이지 동일 복제는 AP-17 위반** — 사진은 모두 깔되 구성(중앙/하단 앵커/split/패널 카드 등)은 페이지마다 다르게.
- **AP-22 요소 잘림 금지**: 카드·텍스트·버튼 등 어떤 요소도 **잘린 채로 완성하지 말 것**. 특히 hero 하단
  오버랩 카드처럼 음수 마진으로 부모 밖으로 나가는 요소가 부모의 `overflow:hidden`에 잘리는 패턴 주의 —
  오버랩 요소를 쓰면 부모는 `overflow:visible`로 두고, 배경 bleed가 필요하면 배경 쪽만 따로 클립한다.
  빌드/수정 후 스크린샷(`scripts/shoot_one.mjs`)으로 데스크탑+모바일 모두 잘림 없는지 확인하고 완료 선언.
- **AP-23 첫 화면(hero) 버튼 금지**: 홈페이지 첫 번째 섹션(hero)에는 CTA 버튼/링크 버튼(`.btn`, `<button>`,
  버튼형 `<a>` "예약하기/전화하기/문의하기/지금 시작" 등)을 넣지 말 것. hero는 배경 사진 + 텍스트(eyebrow·헤드라인·리드)
  + 하단 SCROLL 큐 정도로만 구성하고, **CTA·예약·전화 버튼은 두 번째 섹션 이후 또는 헤더/플로팅 영역으로** 옮긴다.
  (AP-17의 "버튼 2개 복제 금지"를 더 강하게 — 이제 첫 섹션엔 버튼을 아예 두지 않는다.)
- **이미지 소스**: `assets/<category>/` 관련 컷 우선. 정면 얼굴 컷은 확대 crop(`object-position`/`transform
  scale`/강한 오버레이)으로 얼굴을 viewport 밖으로 빼 사용 가능.
- **폰트**: 본문 기본 **Noto Sans KR**. 헤드라인만 화이트리스트 8종에서 다양화 가능 — 프리텐다드,
  페이퍼로지, 프리젠테이션, G마켓 산스, SUIT, Gothic A1, 엘리스 디지털 배움, 제주고딕. **명조/serif 금지**(로고만 예외).

## 품질 게이트
- **정적 채점(코드 규칙)**: 모든 랜딩은 `python3 scripts/score_landing.py` 기준 **80점 초과**를 유지한다(80점 이하는 재제작 대상). 셀 수 있는 규칙(폼·마퀴·픽토그램·폰트·이미지 수·hero CSS)은 스크립트가 강제.
- **비주얼 QA(눈으로만 보이는 것)**: 깨진 이미지·모바일 잘림·AP-13 얼굴·AP-15 타이포·**AP-20 인물 국적** 등 정적 채점이 못 잡는 시각 문제는 `visual-qa` 서브에이전트를 디스패치해 스크린샷 검수. 빌드/대규모 수정 후 또는 출시 전 on-demand로 돌린다(전수 자동 훅 아님 — 비용 절감).
- 빌드/수정 후 점수를 직접 확인한다.

## 서브에이전트 보고 형식
Agent 디스패치 결과는 끝에 **발견 / 수정 / 판단근거** 3-part로 보고한다.
